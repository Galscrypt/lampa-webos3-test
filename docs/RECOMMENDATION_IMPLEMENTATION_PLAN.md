# Compact Smart — план разработки и проверки

## Принцип внедрения

Рабочий `compact.js` версии 0.2.1 остаётся контрольной точкой. Новый алгоритм
включается feature flag и разрабатывается небольшими вертикальными этапами. На
каждом этапе есть автоматический gate и простой возврат к текущим рядам без
переустановки URL плагина.

## Этап 0 — зафиксировать контракт

Результат:

- mock Lampa получает `Favorite`, `Timeline`, `Timetable` и `state:changed`;
- создаются fixture-профили и каталог кандидатов;
- вводятся pure-функции без сетевых вызовов;
- текущие 17 тестов остаются зелёными.

Новые fixtures:

1. новый пользователь без истории;
2. любитель криминальных сериалов;
3. семейный/детский профиль;
4. русскоязычный профиль;
5. любитель классики;
6. смешанный mainstream-профиль;
7. пользователь с большим числом `thrown`;
8. сериал с частично и полностью просмотренными вышедшими эпизодами.

## Этап 1 — безопасная фильтрация

Реализовать модули/функции:

- `readFavoriteSnapshot()` через публичные методы Lampa;
- `mediaKey(card)` и устойчивое определение типа;
- `viewState(card)` для фильма и сериала;
- `isReleased(card, now)`;
- `qualityThreshold(card, now)`;
- `filterCandidate(card, context)` с кодом причины;
- межрядовый `exposureSet`.

Критерии готовности:

- 0 просмотренных фильмов в smart-рядах;
- 0 `thrown`;
- полностью просмотренный сериал скрыт, незавершённый с новой серией не скрыт;
- 0 дублей в первых 20 карточках одного ряда;
- будущий релиз появляется только в «Скоро»;
- фильтр не ломается при неполной карточке и недоступном Timetable.

## Этап 2 — профиль и cold start

Реализовать:

- evidence mapping и recency decay;
- раздельные movie/TV профили;
- положительные и отрицательные веса жанров;
- profile/settings signature;
- три режима cold start;
- пересчёт по `state:changed` с debounce.

Критерии готовности:

- профиль детерминирован для одного snapshot;
- `thrown` снижает соответствующие признаки, но не стирает весь жанр;
- изменение избранного инвалидирует только smart-cache;
- история не записывается в debug и не уходит в сеть;
- вычисление профиля на 300 карточках укладывается в 50 мс в Node fixture.

## Этап 3 — candidate engine

Реализовать единый `CandidateBroker`, который объединяет requests и использует
текущую очередь Compact:

- seed recommendations;
- профильные discover movie/TV;
- trending movie/TV;
- provenance и дедупликацию;
- дневное чередование seeds;
- ограничение пула 80 карточек на тип;
- cache/stale/fallback.

Критерии готовности:

- не более 6 запросов на одно обновление snapshot;
- не более 2 одновременных запросов;
- одинаковые запросы объединяются;
- частичный отказ даёт неполный, но рабочий пул;
- повторное открытие со свежим cache не делает сеть;
- stale выдаётся сразу и обновляется один раз в фоне.

## Этап 4 — ranking и diversity

Реализовать:

- динамические `C` и `m` для Bayesian rating;
- нормализацию каждого компонента в `[0,1]`;
- row-specific веса;
- confidence за независимые источники;
- greedy diversity re-rank;
- детерминированный дневной tie-break;
- explain data для debug, но не визуальные значки в первой версии.

Критерии готовности на fixtures:

- `watchedLeakage = 0`;
- `thrownLeakage = 0`;
- `duplicateRate(first 20) = 0`;
- не более 3 одинаковых primary genre в первых 10;
- средний Bayesian WR результата не ниже исходного допустимого пула;
- карточка с 5 голосами не обгоняет сопоставимую с устойчивой оценкой;
- порядок повторяем в течение суток;
- cold start формирует непустые ряды без `NaN` и фиктивной персонализации.

## Этап 5 — ряды и настройки

Добавить под feature flag:

- `Для вас — фильмы`;
- `Для вас — сериалы`;
- `Новые, которые стоит смотреть`;
- ротируемый четвёртый ряд;
- регион и выбранные подписки;
- выключатель персонализации;
- `Очистить профиль Compact` без очистки истории Lampa;
- локальный debug-режим.

Текущие тренды/quality/theme остаются fallback. После подтверждения новой версии
они не удаляются, а скрываются настройкой, чтобы откат не требовал нового файла.

## Этап 6 — тест на реальном LG

Проверить на телевизоре:

- холодный старт после полной перезагрузки;
- повторное открытие из cache;
- быстрое листание всех рядов;
- возврат из карточки и category_full;
- отключение сети;
- медленный DNS/timeout;
- изменение избранного и `thrown` без перезапуска;
- сериал с новой серией;
- заполненный localStorage;
- 30 минут навигации без роста памяти и зависаний.

Замеряем время до первого ряда, число запросов, максимальную одновременность,
размер cache и субъективную полезность top-10 для каждого fixture-профиля.

## Этап 7 — контролируемый релиз

1. Выпустить как opt-in `compact_smart=false` по умолчанию.
2. Прогнать не менее недели на реальной истории.
3. Зафиксировать неудачные карточки и причину их попадания, не менять веса по
   одному примеру.
4. Калибровать только на наборе кейсов, затем повторять все fixtures.
5. Сделать smart-ряды стандартом лишь после отсутствия функциональных и
   производительных регрессий.

## Матрица автоматических тестов

| Область | Проверка |
| --- | --- |
| Совместимость | ES5 syntax scan, размер runtime, отсутствие Promise/async |
| Контракты Lampa | local/CUB favorite abstraction, Timeline, Timetable, events |
| Безопасность | нет токенов, внешних history endpoints, HTML-инъекций |
| Фильтры | adult, bad keywords, release date, watched, thrown, duplicates |
| Quality | Bayesian formula, возрастные пороги голосов, local-content exception |
| Profile | decay, negative evidence, movie/TV split, cold start |
| Diversity | caps по жанру/creator/franchise/language, cross-row exposure |
| Network | 2 concurrent, 6 calls/snapshot, timeout, coalescing, partial failure |
| Cache | signature invalidation, 8h fresh, 7d stale, 30d seed details, bounds |
| UI | порядок рядов, empty/fallback state, category_full, focus/return |

## Definition of Done первой умной версии

Версия готова не тогда, когда формула написана, а когда одновременно выполнено:

- все старые и новые тесты проходят;
- runtime работает на Chromium 38;
- лимиты запросов, памяти и размера соблюдены;
- просмотренное/брошенное не протекает в рекомендации;
- сериалы обрабатываются по вышедшим эпизодам;
- первые четыре ряда не повторяют друг друга;
- есть рабочий cold start и offline fallback;
- JustWatch корректно указан у provider-данных;
- пользователь может отключить smart-режим и вернуться к стабильной выдаче;
- результат проверен на реальном LG, а не только в mock.

## Отложено осознанно

- облачная синхронизация персонального профиля;
- внешний backend и машинное обучение;
- импорт Letterboxd/Trakt;
- реакции сообщества/CUB как фактор ранжирования;
- полное обогащение всех кандидатов credits/keywords;
- A/B-тестирование между устройствами.

Эти функции могут повысить качество, но требуют отдельного решения по приватности,
инфраструктуре, лицензиям и бюджету запросов. Они не должны блокировать сильную
локальную версию.
